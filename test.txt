Clarifying the completion model for QA-03 before you estimate it.
We're using section-level completion, not slide-by-slide tracking. A section (Core CPD Content, Practical Application, Case Studies) is the unit of record. Slide-level tracking isn't viable right now anyway — the PDF viewer isn't resolving page count (showing 1 / —), so there's no reliable denominator.
A section is marked Complete when either:
1. The learner reaches the final slide of that section, or
2. The learner clicks "Mark complete & continue" — a control available at all times inside the section, not gated on reaching the end
Skipping is allowed and takes one click. We're not marking a section complete purely because the learner navigated away from it — completion needs to be something they did, not something we inferred, since this data backs an accredited certificate.
Cascading display: once a section is Complete, all its slide thumbnails render with the blue tick. But please only store section-level completion — don't write per-slide completion records for slides we didn't observe being viewed. The ticks are derived display, not stored data.
Completion is permanent. Once complete, always complete. Re-entering a finished section doesn't reset it. Same at module and unit level.
Derivation chain (unchanged from the original ticket, and still the core fix):
• Module = Upcoming (not opened, nothing complete) → Active (opened or ≥1 section complete) → Done (all sections complete)
• Unit = Locked → Available / In progress → Completed (all modules Done + assessment passed)
• Invariant: a Completed unit must show every module as Done. No exceptions.
• Padlock icon renders at unit level only, and only for genuinely locked units. Nothing inside an unlocked unit ever shows a padlock — not-started items render muted grey.
Backend question: does the system currently store completion per user below unit level — section or module — or only unit-level scores? If section-level records exist, this is frontend-only. If not, we need a progress write endpoint before the frontend work can land. Please confirm which before estimating.
 
Addition
 
Teachers can navigate by clicking thumbnails directly, not only via the Next button. The rule as written — "section completes when the learner reaches the final slide" — breaks under this, because jumping straight to the last thumbnail would auto-complete a section that was never read. Replacing it:
Track a viewed flag per slide.
• Set to true when the slide renders on screen for ≥3 seconds, by any navigation route — Next button and thumbnail click are treated identically
• Monotonic: once true, never reset. Revisiting a slide changes nothing
• This is an observation, not a completion claim. Record it as viewed, not completed
A section completes when either:
1. All slides in the section have viewed = true — order irrelevant, it's a set not a sequence
2. The learner clicks "Mark complete & continue"
If (2) is clicked with slides still unviewed, show a confirmation: "You've viewed 3 of 8 slides in this section. Mark it complete?"
The "Mark complete & continue" button must always be available and never gated on reaching the last slide. The PDF viewer is currently not resolving total page count (1 / —), which means condition (1) can't evaluate at all in that state. The button is the fallback.
Thumbnail display:
• Not viewed → grey outline circle
• Current → blue ring
• Viewed → blue tick
• Section marked complete → all its thumbnails show blue tick as display only — do not write completed to storage for slides that were never viewed
Leaving a section without completing it has no effect. No auto-complete, no prompt. It stays In progress with its viewed count.
Case Studies: treat each of the two PDFs as its own sub-section with its own completion. The section completes when both do.
Resume behaviour: reopening a partially-viewed section opens at the first unviewed slide, not slide 1.
Revised backend question: does the system store, per user — (a) slide-level viewed flags, (b) section-level completion, (c) both, or (d) only unit-level scores? We need (a) and (b) for this model. Please confirm what exists before estimating.
 
 
Caveat
1. How Slide Checkmarks Work (The 4 Visual States)
• Grey Circle: The teacher hasn't looked at this slide yet.
• Blue Ring ("Now"): The teacher is currently looking at this slide.
• Blue Tick (Viewed): The slide stayed on screen for at least 3 seconds. (This prevents teachers from rapidly clicking through 8 thumbnails in two seconds just to cheat the system).
• Blue Tick (Cascaded): If the teacher clicks "Mark Complete," all remaining grey slides visually turn to blue ticks so the screen looks clean—but the database knows which ones were actually read vs. skipped.
 
 
2. How a Section Becomes "Done"
A section turns "Done" in only two ways:
• Way A (Auto): Every single slide in that section gets marked as "Viewed" (in any order).
• Way B (Manual): The teacher clicks the "Mark complete & continue" button.
• • If they skipped slides: A gentle pop-up appears: "You've viewed 3 of 8 slides in this section. Mark it complete?" [Cancel] / [Mark Complete]. This places the responsibility explicitly on the teacher.
